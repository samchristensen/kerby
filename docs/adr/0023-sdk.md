# 0023. SDK: one package in this repository, published compiled to a private repository

- Status: proposed
- Date: 2026-11-23

## Context

Customers' projects (the owner's own, and clients') call the tenant API over HTTP. Each would otherwise hand-write
clients, copy response shapes and re-derive the error, retry and streaming rules. The shapes already exist as zod schemas
in `packages/contracts`, which the api itself parses requests with. This repository has no build step, its packages are
`workspace:*` and Node refuses to strip types inside `node_modules`, so nothing here can be installed as it stands.

## Decision

- **`packages/sdk` (`@kerby/sdk`) is the client**: a transport (bearer auth, query encoding, time limit, retries of
  idempotent calls and of 429, error mapping to `KerbyApiError` with the API's stable `code`, response validation with
  the contract schemas), one class per resource, and `verifyWebhook` (Standard Webhooks v1, Web Crypto). It reads no
  environment. Its public surface also re-exports the tenant contracts, so a consumer gets one import.
- **Contracts are the source of the types.** `packages/contracts/src/tenant.ts` lists the tenant-facing files; the
  operator and console contracts (Kerby's own wires between services) stay out of the SDK. Response schemas the SDK
  validates with are exported there. Request types are `z.input`, so defaults are optional for the caller.
- **Published as source-of-truth-in-one-place**: `make sdk-publish` ([scripts/sdk.ts](../../scripts/sdk.ts)) compiles the
  SDK with `tsc`, rewrites its `@kerby/*` specifiers to relative paths (the SDK, contracts, and the two port packages the
  contracts take types from are emitted into one tree), writes a manifest whose only dependency is `zod`, adds
  `README.md`, `INTEGRATION.md` (the guide an agent follows) and an `AGENTS.md`, and pushes that tree to the private
  repository `samchristensen/kerby-sdk` as tag `v<version>`. Consumers install `github:samchristensen/kerby-sdk#v<version>`.
  A tag never moves: publishing different contents under an existing version fails and says to raise `version`.
- **Proof is the real stack.** `make sdk-e2e` runs every resource over HTTP against `make up`; the SDK's own logic
  (retries, reconnects, waiting) is tested against a stub server. There are no tests that a method forwards to a route.

## Alternatives

- _Install the monorepo's package by git subdirectory_: needs a build on install, drags `workspace:*` packages, and
  exposes the whole repository's history to every consumer.
- _A bundler (esbuild, tsup) for one output file_: a new dependency and a declaration bundler to maintain, to save a
  thirty-line specifier rewrite and a deeper `lib/` tree.
- _Generate a client from an OpenAPI document_: there is none, and the zod contracts already are the document.
- _npm registry_: a private registry or scope to run for one consumer set; a git tag is enough until there are many.

## Consequences

- A contract change is an SDK change: bump `packages/sdk/package.json` and publish. Consumers on an old tag keep working
  until the API removes what they use; a response that no longer matches fails as `KerbyResponseError`, and
  `validateResponses: false` is the escape.
- The SDK repository is generated; edits there are overwritten.
- `packages/sdk/src/index.ts` is a public entry: knip is told its exports are deliberate.
