# 0006. SDK and integration guide

Goal: the owner's other projects and clients integrate with Kerby through one typed client and one guide an agent can
follow. Decision: [ADR 0023](../../adr/0023-sdk.md).

## Milestones

### S1 The client

- [x] `packages/sdk`: transport (auth, retries, timeouts, error mapping, response validation), SSE reader, polling
- [x] Resources for every tenant route: conversations (ask, stream, streamReply, trace), judgments, events (list, tail),
  search, tools, prompts, subscriptions, tool servers, integrations, model keys
- [x] `verifyWebhook` (Standard Webhooks v1, Web Crypto)
- [x] `@kerby/contracts/tenant` entry: the tenant-facing contracts, without operator and console

### S2 Publishing

- [x] `make sdk-build`: compiled tree with no `@kerby/*` imports, manifest with `zod` only
- [x] `make sdk-publish`: tag `v<version>` in the private `samchristensen/kerby-sdk` repository
- [x] `README.md`, `INTEGRATION.md` (the agent guide) and `AGENTS.md` ship with it

### S3 Proof

- [x] `make sdk-e2e` on the real stack, `make check` and `make test` green
- [x] Installed from the private repository into a scratch project and run against the stack

## Not in this plan

Other languages, an OpenAPI document, a blob upload route (content parts may name blobs; nothing uploads them yet),
a registry (npm) release.

## Log

- 2026-11-23 Built. Findings: `ListConversationsQuerySchema` and friends use `z.coerce`, so their `z.input` is `unknown`;
  the SDK writes its query types out. A stream opened after the post can miss the live `run_end`, so `streamReply` also
  watches `busy` and fills in the missed messages from the REST read. The first stack on the old `pgdata` volume lacked the
  tools tables (a stale tenant database): the SDK proof ran on a fresh compose project (`KERBY_PROJECT=kerby-sdk`).
